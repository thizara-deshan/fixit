Where new code goes:

| Kind of code | Location |
|---|---|
| Request/response shape, enum, validation message | `packages/contracts/src/<domain>/schemas.ts` |
| Business rule that both mocks and API need (state machine, limits, privacy projection, pricing, ranking) | `packages/contracts/src/<domain>/*.ts` as a pure function + test |
| A screen | `apps/web/src/features/<feature>/pages/` |
| Component used by one feature | `features/<feature>/components/` |
| Component used by two or more features | `apps/web/src/components/` |
| shadcn primitive | `apps/web/src/components/ui/` (via `pnpm dlx shadcn add`) |
| HTTP call | `features/<feature>/api.ts`; TanStack hook in `features/<feature>/hooks.ts` |
| Mock behaviour for an endpoint | `apps/web/src/mocks/handlers/<domain>.ts` |
| API endpoint | `apps/api/src/modules/<domain>/` (controller → service) |
| Cross-cutting Nest concern | `apps/api/src/common/` |
| External I/O adapter | `apps/api/src/infra/` |
| Demo/seed data | `packages/fixtures` |

## 2. Contracts package (`@fixit/contracts`)

Rules:
- zod **v4** only; no runtime dependencies except `zod`, `date-fns`, `@date-fns/tz`.
- Every schema exports `const X = z…` and `type X = z.infer<typeof X>` with the same name.
- **Validation messages are the SPEC copy**, written once in the schema. Forms (react-hook-form + `zodResolver`) and the API show the same text.
- API response types are inferred from these schemas. Prisma types never cross a module's mapper; the web never sees them.
- Functions take `now: Date` as a parameter. No `Date.now()` inside contracts.
- Built with tsup (ESM + CJS + d.ts). The `"source"` export condition points at `src/` so Vite and Vitest consume TypeScript directly with no build step; NestJS consumes `dist/` (`pnpm dev` runs `tsup --watch`).

```ts
// packages/contracts/src/common/primitives.ts
import { z } from 'zod';

export const Id = z.string().min(1).max(40).regex(/^[A-Za-z0-9_-]+$/);
export const RequestRef = z.string().regex(/^FX-\d{4,}$/);
export const Lkr = z.number().int().nonnegative();                // whole rupees
export const IsoDate = z.iso.date();                               // 'YYYY-MM-DD' (a Colombo calendar day)
export const IsoDateTime = z.iso.datetime({ offset: true });

export const Email = z.string().trim().toLowerCase()
  .min(1, 'Enter your email address.')
  .pipe(z.email('Enter a valid email address, like name@example.com.'));

export const Password = z.string()
  .min(8, 'Use at least 8 characters with a letter and a number.')
  .max(128)
  .regex(/[A-Za-z]/, 'Use at least 8 characters with a letter and a number.')
  .regex(/\d/, 'Use at least 8 characters with a letter and a number.');

export const FullName = z.string().trim()
  .min(1, 'Enter your full name.')
  .min(2, 'Name must be 2 to 80 characters.')
  .max(80, 'Name must be 2 to 80 characters.');

/** Input: "077 123 4567", "0771234567", "+94 77 123 4567" → output "+94771234567" (E.164). */
export const MobileInput = z.string()
  .transform((s) => s.replace(/[\s-]/g, ''))
  .transform((s) => (s.startsWith('+94') ? s.slice(3) : s.startsWith('0') ? s.slice(1) : s))
  .pipe(z.string().regex(/^7\d{8}$/, 'Enter a Sri Lankan mobile number, like 077 123 4567.'))
  .transform((d) => `+94${d}`);
/** Output form, as stored and returned. Display formatting (+94 77 123 4567) is web-only. */
export const Mobile = z.string().regex(/^\+947\d{8}$/);

export const OptionalReason = z.string().trim().max(500, 'Keep the reason under 500 characters.')
  .optional().transform((s) => (s === '' ? undefined : s));
export const adminReason = (message: string) =>
  z.string().trim().min(10, message).max(500, message);
```

```ts
// packages/contracts/src/common/errors.ts
export const ErrorCode = z.enum([
  'VALIDATION_FAILED',   // 400, fieldErrors set
  'UNAUTHENTICATED',     // 401 (missing/expired token)
  'ACCOUNT_SUSPENDED',   // 401 at login/refresh/any request
  'FORBIDDEN',           // 403 wrong role
  'NOT_FOUND',           // 404 (also: exists but not yours)
  'INVALID_TRANSITION',  // 409, details.reason = TransitionReason, details.status = current status
  'RULE_VIOLATION',      // 422, details.rule = RuleCode
  'CONFLICT',            // 409 unique clash (e.g. email taken → details.rule)
  'RATE_LIMITED',        // 429
  'PAYLOAD_TOO_LARGE',   // 413
  'UNSUPPORTED_MEDIA',   // 415
  'INTERNAL',            // 500
]);
export type ErrorCode = z.infer<typeof ErrorCode>;

/** Business-rule failures the UI maps to SPEC copy (S5.E8, S12 blocked states / E6, S16, S23, S38 …). */
export const RuleCode = z.enum([
  'invalid_credentials', 'email_taken', 'email_unconfirmed', 'token_invalid', 'current_password_wrong', 'password_reused',
  'own_listing', 'provider_unavailable', 'provider_paused', 'mobile_missing', 'open_with_provider', 'open_limit_reached',
  'date_out_of_window', 'town_not_served', 'service_not_offered',
  'review_not_eligible', 'review_window_closed', 'already_reviewed',
  'services_min', 'services_max', 'service_name_taken', 'towns_max', 'onboarding_incomplete', 'documents_missing',
  'verification_not_editable', 'category_in_use', 'name_taken', 'cannot_suspend_admin', 'already_in_state',
]);
export type RuleCode = z.infer<typeof RuleCode>;

export const ErrorEnvelope = z.object({
  error: z.object({
    code: ErrorCode,
    message: z.string(),                                            // developer-facing; UI copy comes from SPEC
    requestId: z.string(),
    fieldErrors: z.record(z.string(), z.array(z.string())).optional(), // VALIDATION_FAILED: path → SPEC messages
    details: z.object({
      rule: RuleCode.optional(),
      reason: z.string().optional(),                               // TransitionReason
      status: z.string().optional(),
      ref: z.string().optional(),                                  // open_with_provider → existing ref
    }).optional(),
  }),
});
export type ErrorEnvelope = z.infer<typeof ErrorEnvelope>;
```

### 2.8 Booking state machine

```ts
// packages/contracts/src/requests/state-machine.ts
export type MachineActor =
  | { kind: 'customer'; userId: string }
  | { kind: 'provider'; userId: string }
  | { kind: 'admin'; userId: string }
  | { kind: 'system' };

export interface MachineRequest {
  status: RequestStatus;
  customerId: string;
  providerUserId: string;
  preferredDate: string;   // IsoDate (Colombo day)
  expiresAt: Date;         // rules.expiresAt(createdAt, preferredDate)
}
export interface TransitionInput { reason?: string | undefined }

export const TransitionReason = z.enum([
  'final_status',          // from Declined/Cancelled/Expired/Completed
  'invalid_transition',    // edge not in PRODUCT §6.1 (incl. same status, → pending)
  'not_allowed_for_actor', // edge exists, but not for this actor kind
  'not_owner',             // customer/provider is not the party on this request
  'expired',               // pending past expiresAt (sweep not yet run)
  'not_yet_expired',       // system expiry before expiresAt
  'past_cancel_deadline',  // customer cancels accepted after 23:59 the day before (BR-30)
  'before_preferred_date', // complete before preferredDate (BR-32)
  'reason_required',       // admin cancel without 10–500 char reason
]);
export type TransitionReason = z.infer<typeof TransitionReason>;
export type TransitionResult = { ok: true } | { ok: false; reason: TransitionReason };

type Target = Exclude<RequestStatus, 'pending'>;
const EDGES: Record<'pending' | 'accepted', Partial<Record<Target, readonly MachineActor['kind'][]>>> = {
  pending:  { accepted: ['provider'], declined: ['provider', 'system'], cancelled: ['customer', 'admin', 'system'], expired: ['system'] },
  accepted: { cancelled: ['customer', 'admin', 'system'], completed: ['provider'] },
};

export function canTransition(
  req: MachineRequest, to: RequestStatus, actor: MachineActor, now: Date, input: TransitionInput = {},
): TransitionResult {
  if ((FINAL_STATUSES as readonly string[]).includes(req.status)) return no('final_status');
  const from = req.status as 'pending' | 'accepted';
  const allowed = to === 'pending' ? undefined : EDGES[from][to];
  if (!allowed) return no('invalid_transition');
  if (!allowed.includes(actor.kind)) return no('not_allowed_for_actor');
  if (actor.kind === 'customer' && actor.userId !== req.customerId) return no('not_owner');
  if (actor.kind === 'provider' && actor.userId !== req.providerUserId) return no('not_owner');

  const expired = now.getTime() >= req.expiresAt.getTime();
  if (from === 'pending') {
    if (to === 'expired') return expired ? yes : no('not_yet_expired');
    if (expired && actor.kind !== 'system') return no('expired');   // human actions on a lapsed request
  }
  if (from === 'accepted' && to === 'cancelled' && actor.kind === 'customer'
      && now.getTime() >= cancelDeadline(req.preferredDate).getTime()) return no('past_cancel_deadline');
  if (to === 'completed' && !canComplete(req.preferredDate, now)) return no('before_preferred_date');
  if (actor.kind === 'admin' && to === 'cancelled') {
    const len = input.reason?.trim().length ?? 0;
    if (len < 10 || len > 500) return no('reason_required');
  }
  return yes;
}
const yes = { ok: true } as const;
const no = (reason: TransitionReason) => ({ ok: false, reason }) as const;

/** Throws a typed error the API filter and mocks map to 409 INVALID_TRANSITION (or 403 / 404, see §7.4). */
export function assertTransition(...args: Parameters<typeof canTransition>): void { /* … */ }
```

### 4.1 `http` client

```ts
// apps/web/src/lib/http.ts
import type { z } from 'zod';
import { AuthSession, ErrorEnvelope, type ErrorCode } from '@fixit/contracts';
import { authStore } from './auth-store';

export class ApiError extends Error {
  constructor(
    readonly status: number, readonly code: ErrorCode | 'NETWORK', message: string,
    readonly envelope?: ErrorEnvelope['error'],
  ) { super(message); }
  get rule() { return this.envelope?.details?.rule; }
  get fieldErrors() { return this.envelope?.fieldErrors; }
}

type Query = Record<string, string | number | readonly string[] | undefined>;
interface Opts<S extends z.ZodType | undefined> {
  method?: 'GET' | 'POST' | 'PUT' | 'PATCH' | 'DELETE';
  query?: Query; body?: unknown; form?: FormData; schema: S; signal?: AbortSignal;
}
type Out<S> = S extends z.ZodType ? z.output<S> : void;

export async function http<S extends z.ZodType | undefined>(path: string, opts: Opts<S>): Promise<Out<S>> {
  let res = await send(path, opts);
  if (res.status === 401 && !path.startsWith('/auth/')) {
    if (await refreshOnce()) res = await send(path, opts);       // exactly one retry
    else { authStore.signOut('expired'); }
  }
  if (!res.ok) throw await toApiError(res);
  if (opts.schema === undefined || res.status === 204) return undefined as Out<S>;
  return opts.schema.parse(await res.json()) as Out<S>;          // contract mismatch → ZodError → S41
}

async function send(path: string, o: Opts<z.ZodType | undefined>) {
  const headers = new Headers({ Accept: 'application/json' });
  const token = authStore.accessToken();
  if (token) headers.set('Authorization', `Bearer ${token}`);
  let body: BodyInit | undefined;
  if (o.form) body = o.form;
  else if (o.body !== undefined) { headers.set('Content-Type', 'application/json'); body = JSON.stringify(o.body); }
  try {
    return await fetch(`/api${path}${toQueryString(o.query)}`, { method: o.method ?? 'GET', headers, body, signal: o.signal, credentials: 'same-origin' });
  } catch (e) {
    if ((e as Error).name === 'AbortError') throw e;
    throw new ApiError(0, 'NETWORK', 'Network error');
  }
}

let refreshing: Promise<boolean> | null = null;
/** Single-flight: concurrent 401s share one refresh. Also used once at boot to restore the session. */
export function refreshOnce(): Promise<boolean> {
  refreshing ??= fetch('/api/auth/refresh', { method: 'POST', credentials: 'same-origin' })
    .then(async (r) => {
      if (!r.ok) { if (r.status === 401) authStore.noteRefreshError(await safeEnvelope(r)); return false; }
      authStore.setSession(AuthSession.parse(await r.json()));
      return true;
    })
    .catch(() => false)
    .finally(() => { refreshing = null; });
  return refreshing;
}
```

`auth-store.ts` is a tiny external store (`useSyncExternalStore`) holding `{ accessToken, me, status: 'booting' | 'guest' | 'signed-in', signOutReason }`. `signOut(reason)` clears the token, `queryClient.clear()`, and the router guard redirects to `/login?next=…` with the S5 banner (`expired`) or suspended message (`ACCOUNT_SUSPENDED`). Logout calls `POST /auth/logout` first. Form values on session expiry are kept per SPEC §6.6 by `useFormDraft(key)` (sessionStorage, excludes passwords and files).

`mapApiErrorToForm(err, setError)` (in `lib/`) applies `fieldErrors` to react-hook-form fields and returns the form-level banner copy for `RULE_VIOLATION`/`INVALID_TRANSITION` from one SPEC copy table (`lib/error-copy.ts`).

```ts
// apps/web/src/mocks/lib/identity.ts
/** Works with mock tokens AND real JWTs (when `auth` is real but this domain is mocked): reads the payload, no verification. */
export function resolveActor(request: Request): MockActor | null {
  const h = request.headers.get('Authorization');
  if (!h?.startsWith('Bearer ')) return null;
  const claims = AccessTokenClaims.safeParse(decodeJwtPayload(h.slice(7)));
  if (!claims.success || claims.data.exp * 1000 <= Date.now()) throw mockError(401, 'UNAUTHENTICATED');
  const user = db().users[claims.data.sub] ?? shadowUserFromClaims(claims.data); // registered against the real API
  if (user.status === 'suspended') throw mockError(401, 'ACCOUNT_SUSPENDED');
  return { userId: user.id, roles: deriveRoles({ isAdmin: user.isAdmin, providerPublished: isPublished(db(), user.id) }) };
}
```

Mock tokens are unsigned JWT-shaped strings (`base64url(header).base64url(claims).mock`) with a 15-minute `exp`, so the refresh path is exercised. The mock refresh "cookie" is a localStorage entry `fixit.mock.refresh` (MSW handlers run in the page, so they can read it).

```ts
export type MockDomain = (typeof MOCK_DOMAINS)[number];

export function parseMockDomains(raw: string | undefined): MockDomain[] {
  const value = (raw ?? 'none').trim().toLowerCase();
  if (value === 'all') return [...MOCK_DOMAINS];
  if (value === '' || value === 'none') return [];
  const list = value.split(',').map((s) => s.trim()).filter(Boolean);

  if (unknown.length > 0) throw new Error(`VITE_MOCK_DOMAINS: unknown domain(s): ${unknown.join(', ')}`);
  return [...new Set(list)] as MockDomain[];
}
```

### 5.4 Discover URL state helper

```ts
// apps/web/src/features/discover/url-state.ts — pure read/write (unit-tested) + one hook
export function readDiscover(sp: URLSearchParams): DiscoverQuery {
  return DiscoverQuery.parse(Object.fromEntries(sp));            // invalid → defaults (.catch)
}
export function writeDiscover(s: Partial<DiscoverQuery>): URLSearchParams {
  const out = new URLSearchParams();
  if (s.q) out.set('q', s.q);
  if (s.loc) out.set('loc', s.loc);
  if (s.cat?.length) out.set('cat', s.cat.join(','));
  if (s.rating) out.set('rating', s.rating);
  if (s.verified) out.set('verified', '1');
  if (s.price) out.set('price', s.price);
  if (s.sort && s.sort !== 'rating') out.set('sort', s.sort);
  if (s.page && s.page > 1) out.set('page', String(s.page));
  return out;                                                     // defaults omitted → canonical URLs
}

export function useDiscoverParams(categories: Category[]) {
  const [sp, setSp] = useSearchParams();
  const state = useMemo(() => readDiscover(sp), [sp]);
  return {
    state,
    /** Search bar submit: new search, PUSH; keeps sort; drops rating/verified/price/page (BR-05, SPEC §8.2). */
    newSearch: (q: string, loc?: string) => {
      const cat = matchCategory(q, categories);
      setSp(writeDiscover({ q: q.trim() || undefined, loc, cat: cat ? [cat.id] : undefined, sort: state.sort }));
    },
    /** Filters, sort, location: REPLACE, page reset. Ticking a category clears q when q was a category match. */
    setFilter: (patch: Partial<DiscoverQuery>) => {
      const clearQ = patch.cat !== undefined && state.q !== undefined && matchCategory(state.q, categories) !== null;
      setSp(writeDiscover({ ...state, ...patch, ...(clearQ ? { q: undefined } : {}), page: 1 }), { replace: true });
    },
    setPage: (page: number) => setSp(writeDiscover({ ...state, page })),       // PUSH
    clearAll: () => setSp(new URLSearchParams()),
  };
}
```

The last Discover URL is stored in sessionStorage (`fixit.lastDiscover`) for S3's back link and S13's "Back to search". The filter-count badge and the Discover query key are derived from `state`.

### 5.5 Optimistic mutation + toast pattern

```ts
// apps/web/src/lib/optimistic.ts
export function useOptimisticMutation<TVars, TData, TCache>(o: {
  queryKey: QueryKey;
  mutationFn: (v: TVars) => Promise<TData>;
  apply: (cache: TCache | undefined, v: TVars) => TCache | undefined;
  errorToast: string;                     // SPEC §6.3 "Couldn't {save / update / remove}. Try again."
  successToast?: (v: TVars) => { message: string; undo?: () => void } | undefined;
  invalidate?: QueryKey[];
}) {
  const qc = useQueryClient();
  const m = useMutation({
    mutationFn: o.mutationFn,
    onMutate: async (v) => {
      await qc.cancelQueries({ queryKey: o.queryKey });
      const prev = qc.getQueryData<TCache>(o.queryKey);
      qc.setQueryData<TCache>(o.queryKey, (c) => o.apply(c, v));
      return { prev };
    },
    onError: (_e, v, ctx) => {
      qc.setQueryData(o.queryKey, ctx?.prev);
      toast.error(o.errorToast, { action: { label: 'Try again', onClick: () => m.mutate(v) } });
    },
    onSuccess: (_d, v) => {
      const t = o.successToast?.(v);
      if (t) toast(t.message, t.undo ? { duration: 8000, action: { label: 'Undo', onClick: t.undo } } : { duration: 4000 });
    },
    onSettled: () => { for (const k of [o.queryKey, ...(o.invalidate ?? [])]) void qc.invalidateQueries({ queryKey: k }); },
  });
  return m;
}
```

Usage per SPEC §6.5: unsave (F-10) passes `undo: () => save.mutate(id)`; pause/resume (F-22) and category reorder (S38) have no undo. Accept/decline/complete/cancel are **not** optimistic: a confirm dialog, then the server call, then the row flash (`primary-flash` 900 ms, keyed by ref in a small `useRowFlash` store) and a toast. A 409 `INVALID_TRANSITION` opens the §6.3 "This request has changed" dialog and refetches. Toasts use shadcn's Sonner (`<Toaster visibleToasts={1} position="bottom-center" />`) styled with tokens.

### 5.6 Errors, 403, 404
- `RouteErrorBoundary` (route `errorElement`): `ApiError` 404 → S39 (variant by route: generic / provider / request); 403 → S40; anything else → S41 with `requestId` (or a client-generated id) as "Error ID".
- Page-level primary queries use `throwOnError: (e) => e instanceof ApiError && [403, 404].includes(e.status)`. Other failures render `<SectionError onRetry>` in place of that card (SPEC §6.3).

- Skeletons: `useDelayedFlag(isPending, 150)` before showing (SPEC §6.1).
- Offline banner: `useOnlineStatus()` in every layout.

## 6. Auth design

### 6.1 Flows
| Flow | Behaviour |
|---|---|
| Register | `POST /auth/register` → argon2id hash (`m=19456, t=2, p=1`), user `active`, `emailConfirmedAt=null`. Creates an `AuthToken(confirm, 24 h)` (random 32 bytes, stored as SHA-256) and emails the link `${APP_ORIGIN}/auth/confirm?token=…`. Responds 204 → S7. `intent=provider` and `next` are kept client-side (sessionStorage) for S8's Continue. Unconfirmed users can log in (SPEC S5). |
| Confirm | `POST /auth/confirm-email {token}` → hash lookup, unexpired, unused → set `emailConfirmedAt`, mark used. Already confirmed → `already_confirmed`. Invalid → 422 `token_invalid` → S8 expired state. |
| Login | `POST /auth/login` → user by lowercased email. Missing user → a dummy argon2 verify (constant time) then 401 `invalid_credentials`. Suspended → 401 `ACCOUNT_SUSPENDED` (checked **after** the password is verified, so suspension isn't revealed to guessers). Issues the access token + refresh cookie. |
| Admin login | `POST /auth/admin/login`: same, but `!isAdmin` → 401 `invalid_credentials` (S29.E4). Admins may also use `/auth/login`; there is no Google sign-in for admins (Google callback with an admin email → error). |
| Google | `GET /auth/google?next&intent` → state + PKCE verifier in a signed, httpOnly, 10-minute cookie → Google. Callback verifies state and exchanges the code (`google-auth-library`). Verifies the ID token (`aud`, `email_verified`). Finds the user by `googleSub`, else by email (links the account and sets `emailConfirmedAt` if null), else creates a confirmed user. Suspended → redirect `/login?error=suspended`. Sets the refresh cookie and redirects to `/auth/google/done?next=…`, where the SPA calls `/auth/refresh`. If `GOOGLE_CLIENT_ID` is unset the routes return 404 and the web hides the button (`VITE_GOOGLE_ENABLED`). Mock mode: the button calls `POST /api/auth/google/mock` (MSW-only route) when `isMocked('auth')`. |
| Refresh | `POST /auth/refresh` with cookie `fx_rt`. Requires `Origin`/`Sec-Fetch-Site` same-origin. Finds the token by hash: valid → mark replaced and issue a new one in the same family (rotation). An already-rotated or revoked token was presented → **revoke the whole family** (theft signal) → 401. The user must be active. Returns `AuthSession`. |
| Logout | `POST /auth/logout`: revokes the family, clears the cookie, 204. |
| Me | `GET /auth/me` → `Me` (roles derived fresh). |
| Forgot / reset | Forgot: always 204. If the user exists and has a password or Google account, creates `AuthToken(reset, 1 h)` and emails it. A Google-only account gets a reset link too, which adds a password. Reset: validate token → new hash → **revoke all refresh tokens** → 204 → S5 toast. |
| Change password | Needs `currentPassword` (`current_password_wrong`), must differ (`password_reused`); revokes all other families. |
| Suspension | A31 sets `status=suspended` and revokes all refresh tokens. `JwtAuthGuard` loads the user on every request, so the very next call gets 401 `ACCOUNT_SUSPENDED` (SPEC §8.4). |

### 6.2 Tokens
- **Access token:** JWT HS256 signed with `JWT_ACCESS_SECRET`, TTL `ACCESS_TOKEN_TTL_SEC` (900). Claims `{ sub, roles, iat, exp }`. The client keeps it in memory only (never in localStorage).
- **Refresh token:** 32 random bytes (base64url) in cookie `fx_rt`: `HttpOnly; Secure; SameSite=Lax; Path=/api/auth; Max-Age=30d`. `Secure` comes from `COOKIE_SECURE` (false only in local http dev). DB row `RefreshToken { tokenHash (SHA-256), familyId, expiresAt, revokedAt, replacedById, userAgent }`. A daily cleanup in the expiry job deletes rows expired for > 7 days.
- **Roles:** derived, not stored. `admin` if `isAdmin`; otherwise `customer`, plus `provider` once the listing is published. The guard re-derives them from the DB on every request, so the claim is only a hint for clients and mocks.

### 6.3 NestJS guards and decorators
```ts
// app.module.ts — global order: Throttler → JwtAuth → Roles
providers: [
  { provide: APP_GUARD, useClass: ThrottlerGuard },
  { provide: APP_GUARD, useClass: JwtAuthGuard },   // @Public() opts out; sets req.user: AuthUser | undefined
  { provide: APP_GUARD, useClass: RolesGuard },     // @Roles('user' | 'provider' | 'admin'); no @Roles on a non-public route = boot error (§7.1)
]
export interface AuthUser { id: string; roles: Role[]; providerId: string | null; emailConfirmed: boolean }
```
- `JwtAuthGuard`: verifies the JWT, then a primary-key lookup `{status, isAdmin, emailConfirmedAt, provider{id, onboardingComplete}}`. Missing user → 401; suspended → 401 `ACCOUNT_SUSPENDED`.
- `RolesGuard` maps the access value: `user` = has `customer` role (non-admin); `provider` = has `provider`; `admin` = has `admin`. Failure → 403 `FORBIDDEN`.
- `@CurrentUser()` injects `AuthUser`. Services take `user.id` / `user.providerId` and **never** an id from the client for "my" resources. Queries for owned resources include the owner in the `where` (`{ ref, customerId: user.id }`), so a miss is a 404 by construction.
- Super admin: `pnpm --filter @fixit/api admin:create --email … --name …` (password from the `ADMIN_PASSWORD` env or prompt) and the dev seed. No API route can set `isAdmin`.
- Rate limits (`@nestjs/throttler`, in-memory, single instance; tracker = IP, plus email for login and forgot):

| Route | Limit |
|---|---|
| login, admin/login | 5/min and 20/h per IP+email |
| register | 5/h per IP |
| forgot-password | 3/h per email, 10/h per IP |
| reset-password, confirm-email | 10/h per IP |
| resend-confirmation | 1/60 s per user |
| refresh | 30/min per IP |

  Exceeding a limit → 429 `RATE_LIMITED` (S5.E8 copy). Set `TRUST_PROXY=true` behind the prod proxy.
- No CORS. `helmet()` with a strict CSP for the API. JSON body limit 100 kB; multipart 5 MB (one file).

## 7. API architecture

### 7.1 Modules
One Nest module per domain (§1). A controller only does: decorators (`@Roles`, `@Public`, `@Throttle`), `@ZBody/@ZQuery/@ZParams` parsing, calling one service method, and `respond(Schema, data)`.

Services own the business logic, ownership, transactions and notifications. `*.policies.ts` holds the DB-dependent checks that wrap contracts functions (e.g. gathering counts for `checkCreateRequest`).

A boot-time check walks all routes (`DiscoveryService`): each must be `@Public()` or have `@Roles()`, and each must match exactly one `ENDPOINTS` entry (method + path). A mismatch throws at startup and fails tests.

### 7.2 Validation and responses
```ts
// common/pipes/zod-validation.pipe.ts
@Injectable()
export class ZodValidationPipe<T extends z.ZodType> implements PipeTransform<unknown, z.output<T>> {
  constructor(private readonly schema: T) {}
  transform(value: unknown): z.output<T> {
    const r = this.schema.safeParse(value);
    if (!r.success) throw AppError.validation(z.flattenError(r.error).fieldErrors); // 400 VALIDATION_FAILED, SPEC messages
    return r.data;
  }
}
export const ZBody = (s: z.ZodType) => Body(new ZodValidationPipe(s));
export const ZQuery = (s: z.ZodType) => Query(new ZodValidationPipe(s));

// common/http/respond.ts — strips unknown keys (zod default), so a mapper can't leak extra fields
export const respond = <S extends z.ZodType>(schema: S, data: z.input<S>): z.output<S> => schema.parse(data);
```
The create-request body is parsed with plain `CreateRequestBody`; the BR-34 window is checked by `checkCreateRequest({ now: clock.now(), … })` and returns `RULE_VIOLATION` `date_out_of_window` (decision 004).

### 7.3 Errors
`AppError(status, code, message, { fieldErrors?, details? })` with factories: `validation`, `notFound`, `forbidden`, `rule(rule, details?)` (422), `transition(reason, status)` (409), `conflict(rule)`. The global `AllExceptionsFilter` maps:
- `AppError` → envelope
- `TransitionError` from contracts → `not_owner` → 404, `not_allowed_for_actor` → 403, others → 409 `INVALID_TRANSITION`
- `ZodError` thrown by `respond` → 500 `INTERNAL` (logged loudly: a contract bug)
- Prisma `P2002` → 409 `CONFLICT`; `P2025` → 404
- `ThrottlerException` → 429
- multer limits → 413; `HttpException` → its status
- anything else → 500

Every response carries `x-request-id` (middleware; reused from the proxy header if present), and the envelope has `requestId`. 5xx are logged with the stack and the request id.

### 7.4 Status changes, transactions, state machine
```ts
// modules/requests/requests.service.ts (pattern for every transition)
async accept(user: AuthUser, ref: string, body: AcceptBody) {
  const now = this.clock.now();
  const id = await this.prisma.$transaction(async (tx) => {
    const req = await lockRequest(tx, { ref, providerId: user.providerId! });   // SELECT … FOR UPDATE; null → AppError.notFound
    assertTransition(toMachine(req), 'accepted', { kind: 'provider', userId: user.id }, now);
    await tx.serviceRequest.update({ where: { id: req.id }, data: { status: 'accepted', agreedPrice: body.agreedPrice ?? null } });
    await tx.requestStatusEvent.create({ data: { requestId: req.id, status: 'accepted', actor: 'provider', actorUserId: user.id, at: now } });
    return req.id;
  });
  this.notifications.requestAccepted(id);              // after commit; logs on failure, never throws
  return respond(ProviderRequestView, toProviderView(await this.records.load(id), now));
}
```
- Every status change, plus the side effects that must stay consistent with it (history row, rating recompute, verification status, audit row), happens in **one** `$transaction` with a row lock on the request (and on the provider row for rating and counters).
- **Create (A11):** lock the customer's `User` row (`FOR UPDATE`) so the BR-33 counts can't race. Gather inputs → `checkCreateRequest()` → `nextval` ref → insert request + `pending` event.
- **Suspension cascade (A31):** in one transaction, for each open request of the user as provider → `system` declined/cancelled with reason `Provider unavailable`; as customer → `system` cancelled with reason `Customer account closed`. Each goes through `assertTransition`. Emails go out after commit.
- **Expiry job:** `@nestjs/schedule` `@Cron('* * * * *')` selects `status='pending' AND expiresAt <= now()` (≤ 200 per run), then for each: transaction + lock + `assertTransition(system → expired)` + event, then emails both parties after commit. It's idempotent (the lock plus the status check make a double run harmless). Tests call `ExpiryJob.run(now)` directly with a `FakeClock`.
- `Clock` is injected everywhere (`SystemClock` in prod, `FakeClock` in tests). Never `new Date()` in services.

### 7.5 Request reference (FX-####)
A Postgres sequence `request_ref_seq` (created in a raw SQL migration). In the transaction: `SELECT nextval('request_ref_seq')` → `FX-${n}`. The seed sets `setval` above the highest fixture ref (fixtures use FX-2037…FX-2061, so the next is FX-2062+). Gaps from rollbacks are acceptable. `ref` is `@unique`.

### 7.6 Discover search
`SearchService.search(q: DiscoverQuery)` builds one parameterized SQL with `Prisma.sql` fragments over a `base` CTE that applies **every filter except category**. Then:
- (a) `SELECT categoryId, count(*) … GROUP BY` → `categoryCounts` (BR-05 "counts reflect all other filters")
- (b) `count(*)` with the category filter → total
- (c) the page with the category filter, ordered by the BR-06 sort and `LIMIT 10 OFFSET …`

All three run in one `$transaction([...])` for a consistent snapshot.

```sql
WITH base AS (
  SELECT p.id, p."categoryId", p."ratingAvg", p."reviewCount", p."baseTownId", p."businessName"
  FROM "ProviderProfile" p JOIN "User" u ON u.id = p."userId"
  WHERE p."onboardingComplete" AND u.status = 'active'                                  -- BR-01
    AND (${text}::text IS NULL OR p."searchText" ILIKE '%' || ${text} || '%' ESCAPE '\')  -- BR-03 (escaped % _ \)
    AND (${loc}::text IS NULL OR EXISTS (SELECT 1 FROM "ServiceArea" a
         WHERE a."providerId" = p.id AND a."townId" = ${loc}))                           -- BR-04
    AND (${minRating}::float IS NULL OR p."ratingAvg" >= ${minRating})                   -- NULL rating excluded (BR-05)
    AND (NOT ${verifiedOnly} OR p."verificationStatus" = 'verified')
    AND (${maxPrice}::int IS NULL OR p."startingPrice" <= ${maxPrice})
)
SELECT id FROM base
WHERE (${cats}::text[] IS NULL OR "categoryId" = ANY(${cats}))                           -- OR across categories
ORDER BY
  -- sort=town and loc set: base-town-first group (BR-06)
  CASE WHEN ${sort} = 'town' AND ${loc}::text IS NOT NULL AND "baseTownId" = ${loc} THEN 0 ELSE 1 END,
  CASE WHEN ${sort} = 'reviews' THEN "reviewCount" END DESC NULLS LAST,
  "ratingAvg" DESC NULLS LAST, "reviewCount" DESC, "businessName" ASC, id ASC
LIMIT 10 OFFSET ${(page - 1) * 10};
```
- Then load the cards for those ids (Prisma `findMany` + include) and keep the SQL order.
- `text` comes from `normalizeDiscoverQuery(q, categories)`: when BR-02 matches, `text` is null and the category joins `cats`.
- `searchText` = lowercased `businessName + ' ' + category.name + ' ' + service names`. It's maintained by the providers service on every relevant write, and by admin category rename (bulk update for that category). It has a pg_trgm GIN index.
- Featured (BR-08) = the same base with `verified AND reviewCount >= 1`, ordered as Top rated, `LIMIT 4`.
- A contract test asserts the SQL order equals `compareProviders()` on the fixture world.

### 7.7 Rating aggregates
`ProviderProfile.ratingAvg` (Float, **rounded to 1 dp**, so display and filter agree) and `reviewCount`. They're recomputed (not incremented) with `ratingFrom()` over the visible reviews inside the transaction that posts, hides or restores a review, after locking the provider row. `startingPrice` / `startingUnit` are recomputed with `computeStartingPrice()` in the same transaction as any service create, update or delete.

### 9.3 Authorization matrix test
Personas: `anon`; `customer` (plain user, owns request R1 and review V1); `otherCustomer`; `provider` (owns listing L1, the provider on R1); `otherProvider`; `admin`. `test/matrix-fixtures.ts` maps **every** `ENDPOINTS` id to a function `(world) => { params, body?, query? }` that builds a *valid* call for the owning persona.

```ts
for (const ep of Object.values(ENDPOINTS)) describe(`${ep.method} ${ep.path}`, () => {
  for (const persona of PERSONAS) it(persona, async () => {
    const world = await freshWorld();                    // per-test reset of the touched rows (fast factory)
    const call = matrixFixtures[ep.id](world);
    const res = await request(app)[verb(ep)](fill(ep.path, call.params)).set(authFor(persona, world)).send(call.body);
    expect(res.status).toSatisfy(expectedFor(ep, persona));
  });
});
// expectedFor: public → not 401/403 · anon on non-public → 401 · role not in ep.access → 403 ·
// otherCustomer/otherProvider on an owner-ruled endpoint → 404 · owner/admin-as-allowed → 2xx|4xx-rule (never 401/403/404)
// and every response body is checked: no other user's email/mobile/address appears unless the endpoint allows it (privacy probe)
```
A guard test fails if any `ENDPOINTS` id lacks a matrix fixture, so a new endpoint can't ship without its matrix rows. A suspended-user persona row checks that every non-public endpoint returns 401.
